# Workflow + timing figure

Standalone scripts for the manuscript's pipeline figure. Nothing here is part of the
installed `patari` package (see the `pyproject.toml` exclude) and nothing under
`src/patari/` is touched by these scripts.

```
figures/
  benchmark_pipeline.py   # imports patari/patato, needs a real scan -> timings.json
  make_workflow_figure.py # matplotlib/numpy/Pillow only -> workflow_figure.{pdf,png}
  images/                 # hand-exported panel screenshots (see checklist below)
  timings.json            # generated by benchmark_pipeline.py
  workflow_figure.pdf/png # generated by make_workflow_figure.py
```

## 1. Export the panels

Export six screenshots from PATARI into `figures/images/` (filenames are set in
`make_workflow_figure.py`'s `CONFIG.panels`):

| file | panel | content |
|---|---|---|
| `raw.png` | (a) | raw time series / sinogram |
| `reconstruction.png` | (b) | reconstruction |
| `unmixed.png` | (c) | unmixed |
| `us.png` | (d) | ultrasound |
| `segmentation.png` | (e) | segmentation mask |
| `unmixed_roi.png` | (f) | unmixed + ROI overlay |

Checklist for the export (the script cannot verify any of this for you):

- **Same scan, same frame, same wavelength** across all six panels.
- **Same field of view** across the five spatial panels (all but the raw time series), so
  that after the script's identical crop they stay physically comparable and a single
  scale bar is valid for all of them.
- **Identical contrast settings** per modality. Use PATARI's fixed-contrast workflow
  (auto-contrast `continuous`, then `once`) so the reconstruction and unmixed panels
  aren't each auto-scaled to a different window.
- **Exactly one scale bar**, baked into one panel of your choice. No colorbars in any
  panel.
- **No PATARI UI chrome** — no layer list, no dock borders, no title bar. Canvas only.
- **Segmentation class labels in English**, not the German names the current models use.
  Either rename the classes before exporting, or crop the legend out of the screenshot
  and let the script draw one instead (`CONFIG.show_segmentation_legend = True` +
  `CONFIG.class_names`/`class_colors` in `make_workflow_figure.py`).

Screenshots don't need matching sizes or aspect ratios — `make_workflow_figure.py`
crops each to a square and resamples all six to a common pixel size. If a panel needs a
non-centred crop (typical for the raw time series, since the informative part of a
sinogram usually isn't centred), add an override to `CONFIG.crop` in
`make_workflow_figure.py`, e.g. `crop={"raw": (120, 900)}` (pixel bounds in the source
image, along whichever axis gets trimmed to make it square).

## 2. Measure timings

```bash
python figures/benchmark_pipeline.py --scan /path/to/Scan_1 --label workstation
```

`--scan` takes either an iThera scan folder (containing a `.msot` file) or a `.hdf5`
export (PATATO or IPASC layout both work — reconstruction runs off the raw time series,
which both formats preserve, not off pre-rendered images). `--label` is appended to the
output filename (`timings_workstation.json`) so the same scan benchmarked on two
machines doesn't overwrite either result; pass `--output` to name it explicitly instead.

Repeats and warm-ups (`--repeats`, default 10; `--warmup`, default 3) apply to every
step. Warm-up runs are mandatory: JAX traces and compiles the reconstruction algorithm on
its first call, and ONNX Runtime builds its segmentation session on its first inference.
Both are timed anyway on their *build* (recorded in `timings.json` under
`model_loading`, excluded from the per-step means) so the manuscript can report that as a
one-time cost separately, per the recommendation in the figure spec.

Other flags (`--reconstruction-preset`, `--unmixing-preset`, `--segmentation-model`,
`--roi-shape`/`--roi-width-mm`/`--roi-height-mm`/`--roi-top-margin-mm`,
`--roi-tissue-class`, `--frame`, `--channel`) select which preset/ROI/frame gets
benchmarked; defaults are the package's built-in clinical presets. Run
`python figures/benchmark_pipeline.py --help` for the full list.

The script prints a summary table and writes the full JSON (per-step means/SDs,
model-loading one-time costs, the ONNX Runtime execution provider actually bound to the
segmentation session, CPU/RAM/OS/GPU, and package versions).

Rename or copy the result to `figures/timings.json` before running the figure script
(or point `CONFIG.timings_json` in `make_workflow_figure.py` at whichever file you want
to plot).

### Running this on a machine with only the PATARI binary installed

`benchmark_pipeline.py` needs `patari`/`patato`/`onnxruntime`/`jax`/`numpy` importable,
which normally means a dev checkout. You don't need one to test another machine: PATARI's
binary is built with [PyApp](https://github.com/ofek/pyapp) (see
`.github/workflows/build-pyapp.yml`), which on first run downloads a real CPython,
creates a managed virtualenv, and `pip install`s the built `patari` wheel into it — every
dependency this script needs is already sitting there as an ordinary site-package, it's
just not on `PATH` as a plain `python`.

PyApp exposes that interpreter directly through its own management commands:

```bash
# macOS/Linux
./patari-<version> self python benchmark_pipeline.py --scan /path/to/scan --label <machine-name>
```
```powershell
# Windows
.\patari-<version>.exe self python benchmark_pipeline.py --scan C:\path\to\scan --label <machine-name>
```

Copy just `benchmark_pipeline.py` to the target machine (no other file in `figures/` is
needed — it writes its output next to wherever it sits) and run the command above. The
first run on a fresh install pays the same one-time bootstrap cost as launching the GUI
for the first time (downloads CPython + all dependencies, needs internet); after that
it's instant. Copy the resulting `timings_<machine-name>.json` back for `make_workflow_figure.py`.

This is arguably *more* representative than a dev/conda env, since it benchmarks the
exact pinned `patari`/`patato`/`onnxruntime`/`jax` versions that ship in that release, not
whatever happens to be in a local editable install. `self python-path` also exists if you
just want the interpreter's path rather than running a script directly with it.

## 3. Build the figure

```bash
python figures/make_workflow_figure.py
```

Reads `figures/images/*.png` and `figures/timings.json`, writes
`figures/workflow_figure.pdf` (vector, panel titles/timing text stay text; the panel
images themselves are embedded raster, which is expected) and a 300 dpi
`figures/workflow_figure.png` preview.

No PATARI import — matplotlib, numpy and Pillow only, so it stays runnable without the
rest of the stack.

## What to edit to regenerate

- **New/updated panel screenshots** → re-export into `figures/images/`, re-run
  `make_workflow_figure.py`.
- **New timing numbers** (different scan, different machine, different presets) →
  re-run `benchmark_pipeline.py`, then `make_workflow_figure.py`.
- **Page width** → `CONFIG.fig_width_in` in `make_workflow_figure.py`. Get the real value
  from the manuscript: put `\the\textwidth` in the `.tex` and divide the result (in pt)
  by 72.27 to get inches.
- **Layout spacing, fonts, arrow style, panel border, segmentation legend** → all in the
  `CONFIG` dataclass at the top of `make_workflow_figure.py`.
- **Which preset/frame/ROI gets benchmarked** → CLI flags on `benchmark_pipeline.py`, or
  the `Config` dataclass defaults at its top.

## Notes

- Never hand-edit `timings.json` — every number in the figure comes from it, and the
  figure script fails loudly if it's missing or a key is absent rather than falling back
  to a placeholder.
- `benchmark_pipeline.py` needs the segmentation model already downloaded to
  `get_user_models_dir()` (launch PATARI once so it can fetch it, or download it from the
  URL in `segmentation_models.json`) and, for reconstruction, whichever DeepMB ONNX
  weights the chosen preset references.
